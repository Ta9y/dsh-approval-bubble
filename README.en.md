# dsh-approval-bubble

The whole plugin except this sentence was generated by DeepSeek Harness

A DSH (DeepSeek Harness) desktop plugin: when a **background session** needs interaction (permission approval, option question, or plan confirmation), it pops a bubble card beside that session's sidebar row so you can resolve it in place without switching sessions.

> 中文说明: [README.md](./README.md)
>
> GitHub: <https://github.com/Ta9y/dsh-approval-bubble>

## Features

- **Permission requests**: shows tool name and reason; one-click **Reject / Allow once**, plus translate and copy.
- **Option questions**: single / multi select, free-text "Other answer…", skip / previous / next / submit; multi-question paging and a recommended badge.
- **Plan review**: plan headline and summary, expandable full text, one-click approve, open session.
- **Draggable**: drag by the header; the position is pinned after dragging. A new request re-anchors beside its session row.
- **Responsive width**: about 26% of the window width, clamped to 268–420px, updated live on window resize.
- **Color-coded**: orange = permission approval; blue = questions / plan review.
- **Fallback placement**: when the session row is not visible (collapsed workspace, icon rail, scrolled out), bubbles stack in the bottom-right corner instead.
- **No duplicate prompt**: the session open in the main view is skipped (the built-in composer owns it).

## ⚠️ High-risk permission usage (must read)

This plugin surfaces and **submits permission decisions on your behalf**; "Allow once" is a high-risk action:

1. **"Allow once" grants elevated execution for this one tool call.** It can mean file writes outside the workspace, command execution, or network access; the DSH Host executes in-process, **outside the workspace sandbox**, and the decision cannot be undone.
2. **Always read the tool name and reason before deciding.** The reason text may be model-generated and is not a security guarantee; choose **Reject** when unsure.
3. This plugin **never auto-approves**, never bypasses, and never weakens any approval policy. Every grant requires a click from you, and no new model-facing tools are added.
4. **Translate** sends the current bubble text (reason / question and options / plan summary) to Microsoft Bing's anonymous translation endpoint (falling back to Google's anonymous endpoint when Bing is unavailable); **do not translate requests containing sensitive information**.
5. **Copy** writes the current content to the system clipboard; other programs may read it.
6. The plugin writes no session logs and uploads no telemetry. The Host registers exactly one loopback, same-origin-guarded translation route (`/dsh-approval-bubble/translate`).

## Requirements

- DSH desktop `0.2.1-rc.2` or newer, profile named `desktop`;
- HMR enabled in that profile (default).

## Install

CLI (Windows; `dsh` lives under the DSH installation's `runtime\cli\bin`):

```powershell
dsh plugin --profile desktop add "file:<absolute path to this repository>"
```

Or via the GUI: **Settings → Plugins → install**, pick this folder. Installation appends `dsh-approval-bubble`
to the profile's `dsh.profile.bundles` and hot-loads it; restart DSH once if it does not appear.

## Usage

1. Switch the main view to **another session** (making the target session a background one);
2. When that background session needs approval / an answer / a plan confirmation, a bubble appears beside its sidebar row;
3. Resolve it in place; drag by the header to move the bubble.

## Look and colors

- Permission approval: `--dsw-alias-state-warn-*` (amber, `#f59e0b` in both themes);
- Questions / plan review: `--dsw-alias-state-business-primary` (light `#4176e6` / dark `#7aaaff`);
- Note: this product's `--dsw-alias-brand-primary` is monochrome ink, not blue — do not use it as an accent.

## Permissions & interfaces

| Direction | Interface / data | Purpose | Frequency |
| --- | --- | --- | --- |
| Read (client) | `uiSession.sessionStatus` (Map) | discover pending interactions and answerability | status events + ~100ms layout loop |
| Read (client) | `sessions.list` | session titles and the main-view flag | same |
| Read (client) | `locale` service | zh/en strings | locale change events |
| Write (local) | `POST /dsh-approval-bubble/translate` | translate bubble text | on a "Translate" click |
| Probe (local) | `GET/POST /dsh-approval-bubble/ping` | self-check: page load / slot mounts / bubble counts | page load and layout changes |
| Outbound | Bing Edge anonymous endpoint (Google fallback) | machine translation | once per "Translate" click |

- No model-facing tools, no session-event listeners, no session logs, no workspace file access.
- Both local routes are registered inside `ctx.effect` and disposed on unload / hot reload.

## Privacy

- The bubble only reads session status (`uiSession.sessionStatus`) and session titles, never message bodies;
- Translation is an explicit click-triggered action; the text goes only to Bing's anonymous endpoint (with a Google fallback when Bing is unavailable) and never to a server of ours;
- No telemetry, no log files, no local storage.

## Known limitations

- The session shown in the main view never gets a bubble (built-in composer takes over);
- Only the highest-priority pending interaction per session is surfaced (system rule);
- Invisible rows fall back to a bottom-right stack instead of row alignment;
- No browser automation; visual and click verification are real-device only.

## Uninstall

```powershell
dsh plugin --profile desktop remove dsh-approval-bubble
```
